## Fuera de este inventario

- **`companies`** (el recurso entero): el plan lo menciona "si no aplica". Para B2B sí aplica (cliente = empresa), así que **no** se propone borrar. Si se decide lo contrario, usar la skill `delete-initial-resource`.
- **`sales`, `deals`, `contacts`, `tasks`, notas, `tags`**: se reutilizan (CLAUDE.md §4, Modelo de datos).
- **`delete_note_attachments`, `merge_contacts`, `users`, `update_password`**: Edge Functions que el CRM sigue usando.

## Orden sugerido de limpieza (de menor a mayor riesgo)

1. **Desactivar telemetría** (ítem 13): una prop, cero archivos borrados.
2. **`doc/`** (ítem 1): carpeta aislada; solo tocar `makefile` y la cita en `AGENTS.md`.
3. **GitHub Pages y changelog** (ítems 11 y 14): scripts sueltos sin consumidores en la app.
4. **Idioma francés** (ítem 12): junto con la tarea de i18n en español.
5. **Registro shadcn** (ítem 5): primero el hook `.husky/pre-commit`, luego el resto; probar un commit de prueba.
6. **Postmark** (ítem 6): Edge Function + `config*.toml` + variables + sección de configuración. Verificar `typecheck`, `test:unit:functions` y `test:unit:app`.
7. **MCP + OAuth server** (ítem 7): toca rutas de `CRM.tsx` y la configuración de auth; hacerlo antes de cargar datos reales.
8. **Servidor Storybook** (ítem 4a): solo `.storybook/`, scripts y plugin de ESLint; las stories se quedan.
9. **Decisiones de dominio** (ítems 8, 9, 10): requieren Ignacio y, en 8 y 10, migración de base de datos.
10. **Demo, FakeRest y stories** (ítems 2, 3, 4b): lo más riesgoso, porque los tests unitarios dependen de ellos. Solo después de reescribir esos tests.

Cada paso en su propio PR (`fase-1/limpia-<item>`) con `npm run typecheck`, `npm run lint` y `npm run test:unit:app -- --run` en verde.
